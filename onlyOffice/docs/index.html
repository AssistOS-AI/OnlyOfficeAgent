Document Editing Boundary

The pinned OnlyOffice integration provides an authenticated control service and a narrowly public editor transport. It owns session state, tokenized document configuration, callbacks, drain behavior, and the boundary between ordinary workspace files and DPU Confidential storage.

Runtime Behavior

OnlyOffice is disabled by default in Explorer. An administrator can enable onlyOffice from Marketplace to make Office editing available. The manifest restricts it to global runtime mode ("enableModes": ["global"]) so it can access workspace files; Marketplace offers no other mode. Until then, Explorer presents an enablement message when an Office document is opened.

The Runtime-v5 contract exposes authenticated control on target 7000 and public editor transport on target 8080. The agent validates the exact Router-installed forwarding tuple and uses generation-bound sessions before contacting DocumentServer.

Ordinary workspace documents use workspace storage. Confidential documents require a Router-minted dpuConfidential delegation and are read or written through dpuAgent. Browser credentials are removed before requests reach DocumentServer.

System Outline

Editor Assets

Spellcheck uses the narrowly allowed language dictionary files. Third-party editor plugins and their background updater are disabled. Explorer preloads the native versioned status image before editor readiness, keeping disconnect messages complete during a targeted restart.

Development Contract

The design specifications define Runtime-v5, editor, callback, storage, and restart contracts. DS001-coding-style.md is the canonical coding and test-organization reference. Focused Node.js regression tests live under tests/ and run with node --test tests/*.test.mjs. The OnlyOffice wiki is the canonical source for local terminology.
